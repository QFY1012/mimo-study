冻结 94 亿参数，只训练旁边那 1.6 亿

LoRA 不改原来的大矩阵 W，而是在旁边挂两个很窄的小矩阵 B 和 A，用它们的乘积表示"要改多少"。下面每一节都可以动手调，数字按 MiMo-V2.6-Distill-Qwen-9B 的真实形状计算。

1形状：ΔW = B · A

微调就是把 W 改成 W + ΔW。LoRA 假设 ΔW 只沿少数几个方向变化，于是用一个高而窄的 B（d_out × r）乘一个矮而宽的 A（r × d_in）来表示它。r 就是那条"窄缝"的宽度。拖动 r 看看窄缝有多窄。

2数据怎么走：两条路相加

输入 x 同时走两条路。上面是原来的 W，参数冻结、没有梯度；下面先被 A 压到 r 维，再被 B 展开回 d_out 维，乘上缩放系数 α/r 后与上面的结果相加。计算顺序是先 A 后 B，训练时从不把 B·A 这个大矩阵乘出来。

y = W·x + (α / r) · B·(A·x)

3动手训练：r 够不够

这里在浏览器里真跑一个小 LoRA（16 × 16）。先随机造一个"真实变化" ΔW，它的秩是 k；再用秩为 r 的 B·A 去逼近它（Adam + 余弦退火，1500 步）。注意两件事：第 0 步 A 的梯度恰好是 0，因为 B 初始化为 0；r 小于 k 时 loss 会停在一条线上，那条线就是"秩为 r 的矩阵最好能做到的程度"。

4α / r：旁路的音量旋钮

旁路输出要乘一个缩放系数。标准 LoRA 用 α/r，rsLoRA 用 α/√r。如果固定 α 去改 r，系数会跟着变，相当于悄悄改了学习率。常见做法是 α = r（系数为 1），并且把 LoRA 的学习率设得比全参数高一个数量级左右。

5显存账：省了什么，没省什么

LoRA 省掉的是 W 的梯度、fp32 主权重和 Adam 状态，这部分在全参数训练里是大头。但激活值一点没省：反向传播仍要穿过冻结的 W，把梯度传给前面的层。所以上下文越长，两边一起涨。拖动上下文长度看看。

16K
bf16 权重 18.8 fp32 梯度 37.6 fp32 主权重 37.6 Adam m+v 75.3 LoRA 参数+梯度+Adam 2.6（r=64） 激活（每层输入检查点，估算） 单卡 80GB

单位 GB。激活只算了全量重计算时每层保留的输入（32 层 × 长度 × 4096 × 2 字节），每层内部的临时内存和 logits 另计，实际会更多。推理引擎的权重和 KV cache 在训练阶段会被释放，没有画进来。

6合并进 bf16：小更新会被抹掉

训练完可以把旁路并回去：W′ = W + (α/r)·B·A，推理零开销。但 bf16 只有 8 位有效数字，在 0.02 附近，相邻两个能表示的数相差约 1.2 × 10⁻⁴。比半个间隔还小的更新，加上去会被四舍五入回原值。RL 训练里如果每步都合并后同步给推理引擎，推理端拿到的模型可能根本没变。

7放回 RL 里看

r 不用太大

一条轨迹只换回一个奖励分数，能教给模型的信息很少，r = 16–64 通常够用。r = 64 只比 r = 16 多约 2GB，是买个保险。

参考模型是免费的

关掉 adapter 就是原模型。需要算 KL 时，不必再加载一份 18.8GB 的参考模型。

同步要小心精度

不合并时每步只需同步约 0.3GB 的 A、B。必须合并时，每次都从原始 W 加上 fp32 的 ΔW 重新算，并监控训练端和推理端 logprob 的差值。
