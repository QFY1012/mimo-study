# LoRA 原理入门

> 配套可运行代码：`examples/lora_demo.py`（只需 CPU，几秒就能跑完）。下文引用的数字都来自这个脚本的实际输出。

## 1. 要解决什么问题

全参数微调要更新每个权重矩阵 W。对 9B 模型来说，梯度、fp32 master 权重和 Adam 状态加起来约 169GB，而且每个任务都要另存一份完整的模型。

LoRA（Hu et al., 2021）的出发点是一个经验观察：**微调时权重的变化量 ΔW 往往是"低秩"的**。也就是说，ΔW 虽然是一个很大的矩阵，但它实际包含的信息可以用少数几个方向来表达。原论文中，GPT-3 175B 只微调 Wq 和 Wv，r=1 或 2 在部分任务上就已经够用。

## 2. 核心公式

```
原来：  y = W x                        W: d_out × d_in
LoRA：  y = W x + (α / r) · B A x      A: r × d_in，B: d_out × r，W 冻结
```

- 用两个瘦长矩阵的乘积 `B·A` 来表示 ΔW。r 是中间的维度，称为秩（rank）。
- 参数量从 `d_out × d_in` 降到 `r × (d_in + d_out)`。以 9B 模型的 gate_proj（4096→12288）为例，r=64 时 LoRA 只有原矩阵的 2%。
- 计算顺序是先算 `A x`（降到 r 维），再乘 B。**训练时不需要把 B·A 这个大矩阵乘出来。**

## 3. 初始化：A 随机，B 全为 0
- 因为 B=0，一开始 `B A x = 0`，模型和原来完全一样（demo 第 2 节：输出差值为 0.0）。
- 由此带来一个容易忽略的细节：**第一步只有 B 有梯度**。A 的梯度等于 Bᵀ乘上游梯度，而 B=0，所以 A 的梯度也是 0（demo 第 3 节：|grad A| = 0，|grad B| = 2.1e-2）。B 被更新之后，A 才开始被训练。W 自始至终没有梯度。

## 4. 缩放系数 α/r
- α 用来控制旁路输出的幅度。如果固定 α，换 r 时旁路输出的量级会变，学习率也就得重新调。
- 常见做法是把 α 设为 r（缩放系数为 1）或 2r。rsLoRA 提出改用 α/√r，这样 r 很大时也比较稳定。
- 经验上，LoRA 的学习率比全参数微调高大约一个数量级。

## 5. r 应该取多大：能表达多复杂的变化
demo 第 4 节：构造一个变化量的秩恰好为 4 的目标，再分别用不同的 r 去拟合：

| r | 最终 MSE |
|---|---|
| 1 | 0.65 |
| 2 | 0.40 |
| **4** | **2.8e-8** |
| 16 | 2.0e-8 |

当 r 小于真实变化的秩时，无论怎么训练都拟合不到位；r 达到或超过真实的秩之后就能拟合，再继续加大 r 也不会更好。真实模型中 ΔW 的"有效秩"无法预先知道，所以 r 主要靠经验选。RL 中每条轨迹只提供一个标量奖励，信息量少，通常 r=16–64 就够了。

## 6. 为什么省显存，以及哪些地方不省

| | 全参数 | LoRA |
|---|---|---|
| W 的梯度、优化器状态 | 需要（每参数约 16 字节） | **不需要** |
| A、B 的梯度、优化器状态 | — | 需要，但参数量只有 1–2% |
| 激活值 | 需要 | **仍然需要**：反向传播要穿过冻结的 W，把梯度传回前面的层 |
| 反向计算量 | 输入梯度 + 权重梯度 | 只算输入梯度，省掉大约 1/3 |

也就是说，LoRA 节省的是"参数相关的状态"，长序列训练时激活值占用的显存一点也不会少。所以上下文长度仍然是单卡训练的瓶颈。

## 7. 合并：推理时零额外开销
- 训练结束后计算 `W' = W + (α/r)·B·A`，旁路可以去掉，推理速度和原模型一样（demo 第 5 节：fp32 下合并前后的输出差值约 1e-6）。
- 也可以不合并，保留一个基座加多个 adapter，按任务切换（多 LoRA 服务）。

## 8. 合并到 bf16 时的精度陷阱（和 RL 直接相关）
demo 第 6 节：在典型量级为 0.02 的 bf16 权重上加一个很小的更新，再看有多少元素没有变化：

| 更新量 | 合并后没有变化的元素比例 |
|---|---|
| 1e-3 | 0% |
| 1e-4 | 12% |
| 1e-5 | 85% |
| 1e-6 | 98% |

RL 训练时，如果每步都把 LoRA 合并进 bf16 权重再同步给推理引擎（SGLang 目前要求 `merge=True`），训练初期 ΔW 很小，**相当一部分更新在推理端会被舍入掉**。结果是训练端和推理端用的模型不一致。缓解办法：
- 用支持原生 LoRA 的推理引擎（不合并，单独计算旁路）；
- 每次都从 fp32 的 W 和 fp32 的 ΔW 一起合并后再转 bf16，**不要在已经合并过的 bf16 权重上继续累加**；
- 监控训练端和 rollout 端的 logprob 差值。

## 9. 常见变体
- **QLoRA**：基座权重量化成 4-bit（NF4），在上面训练 LoRA。显存再降约 3/4，代价是速度变慢、精度略有损失。
- **DoRA**：把权重拆成"大小"和"方向"两部分，用 LoRA 只更新方向，大小单独学习。
- **rsLoRA**：缩放系数改为 α/√r。
- **只加在部分层上**：例如原论文只加 Wq、Wv；现在一般加到所有线性层效果更好。

## 10. LoRA 在 RL 里的几个好处
- **参考模型零成本**：关掉 adapter 就是原模型，计算 KL 时不需要再加载一份模型。
- **权重同步的数据量小**：不合并的话，每步只需要同步 A、B，约 0.3GB（bf16），全参数则是 18.8GB。
- **试错成本低**：可以对同一个基座跑多组超参，每组只需保存几百 MB 的 adapter。
